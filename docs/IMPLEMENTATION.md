# LovePage 实施记录

## 已确定的范围

沿用 Astro 静态站与浪漫主题，先部署公开示例版；后续由维护者接收照片和信息并修改配置后重新发布。不增加在线编辑、存储后台或登录系统。

## 批次与验收

1. 专属配置、本地占位资源与示例标记：所有示例内容明确标识，保留后续替换入口。
2. 子路径与部署：资源、语言页面、分享封面、manifest 与 sitemap 统一使用 `/LovePage/`。
3. 综合自检：定向单元测试、生产构建、构建产物检查、Chrome 桌面与手机布局及交互验证。
4. 创建公开仓库并发布：确认 Actions 成功、匿名访问与资源状态正常。

路径与部署属于跨组件行为变化，以综合差异自检、定向测试与真实浏览器检查覆盖；当前无需引入额外应用架构。

## 当前状态

内容、资源与路径适配已完成。5 项定向测试、生产构建与三个页面的产物检查已通过（Node 22.15.0，Astro 5.18.2）。独立审查发现图片数量断言会阻止合法的小型相册发布，已移除，保留实际资源引用检查。

Chrome 实测确认计时实时变化、本地插画加载、照片切换及浅色主题正常；发现原项目隐藏照片按钮因 Tailwind `visible` 类覆盖继承可见性而拦截首页点击，已增加隐藏层 `inert` 和指针状态。修复后成功生成带示例标记的纪念卡，实际 PNG 已下载到本机（1080×1440）。测试工具的下载事件等待超时，但文件系统确认下载成功。

尝试进入 390×844 手机尺寸验收时，浏览器控制被 Work 设置禁用；手机视觉检查、照片关闭再生成卡片的完整复验和线上 Chrome 刷新检查待恢复浏览器控制后补充。线上匿名 HTTP 检查将继续执行。正式照片、姓名、日期和音乐尚未提供。

## 依赖状态

兼容范围更新锁文件后，npm audit 从 21 项降为 9 项：1 critical、7 high、1 low。剩余涉及 Astro 5 与压缩/构建依赖，部分修复要求跨主要版本升级，部分暂无兼容修复。本批保留 Astro 5，不执行强制升级。

当前只发布由维护者提供内容生成的静态文件，没有服务端、在线上传或不可信 AVIF 输入。仍需在后续框架升级时处理这些告警，不应将当前状态理解为审计零风险。参考：[Astro define:vars 注入边界](https://github.com/advisories/GHSA-j687-52p2-xcff)、[AVIF 处理的适用条件](https://github.com/advisories/GHSA-26w7-cxv4-gfx2)。
